# 체험수학 개념서: 교육 근거와 과목별 모듈안

## 제작 원칙

- 학생용 이름은 모두 `{학년·과목} 개념서`로 통일한다. 기존 판본 카탈로그의 2015·2022 구분은 유지하고, 성취기준 대조 전에는 과목 간 대응을 확정하지 않는다.
- 설명은 짧게 쓰되 정의·조건·이유·반례를 생략하지 않는다. 먼저 예측하게 하고, 조작 결과를 관찰하고, 말이나 식으로 설명한 뒤, 새 문제로 확인한다.
- 원본은 압축 가능한 JSON + HTML/SVG/CSS/JS 조각을 우선한다. 영상 파일은 기본 생성하지 않는다. 애니메이션은 정지해도 이해 가능하고, 이전/다음·재생/정지를 학생이 제어하도록 한다.
- 기존 `BookData`/`BookWidget`의 지면·그래프 블록과 파라미터 슬라이더는 현재 코드에서 확인된 재사용 경로다. HTML 애니메이션 삽입, 자유 입력 채점, Socratic 분기, 학습 진도 저장은 각각의 런타임 동작이 확인되기 전까지 앱 기능으로 약속하지 않는다.
- 외부 교재·저작물은 단원 구성과 설명 방식의 참고 자료로만 쓰고 문장·문항·도형을 복제하지 않는다. 자체 설명·자체 문항을 작성하고, 외부 자료를 실제 재사용할 때는 라이선스를 별도로 확인한다.

### 교육과정 적용 시기 확인 (2026-10-11)

- 교육부 고시 제2022-33호는 수학과 교육과정을 별책 8로 지정하고, 2022 개정 교육과정의 중학교 1학년·고등학교 1학년은 2025년, 중2·고2는 2026년, 중3·고3은 2027년 3월부터 순차 시행하도록 정한다. 이 고시는 종전 교육과정의 폐지 시점을 2027년 2월 28일로 명시한다.
- 따라서 현재 학년별 제작·시험 범위는 개정판과 시행 학년을 함께 기록한다. 2015 개정 자료는 2022 개정 자료와 이름만으로 합치지 않는다.
- 초기 텍스트 전용 HWP 변환은 성취기준 표 행을 누락했지만, 후속 HTML 변환으로 표를 복구해 아래 5개 중학교 성취기준 코드·문구를 원문에서 대조했다. 그 외 코드는 각각의 원문 대조 전까지 후보로 유지한다.

### 2022 수학과 별책 8 직접 추출 감사 (2026-10-12)

- 교육부 고시 제2022-33호 첨부 `(붙임2) [별책5_14] ... .zip`에서 `[별책8] 수학과 교육과정.hwp`를 분리했다. pyhwp 텍스트 변환과 HTML 변환본의 표 셀을 각각 대조했다. 원본 HWP SHA-256: `AAB8EED59ECF244223D04AFAD75F4CF5AC5085FADCFC3CF52C2F6D54DDFC7856`.
- 본문에서 중학교 ‘변화와 관계’ 교수·학습 지침으로 함수 개념을 “한 양이 변함에 따라 다른 양이 하나씩 정해지는 두 양 사이의 대응 관계”로 도입하고, 여러 상황으로 일차함수·이차함수의 의미를 다루며, 공학 도구로 함수 그래프를 그리고 성질을 탐구하도록 하는 문장을 확인했다. 이는 입력·출력 조작, 예측, 표·그래프 동시 관찰 및 학생 직접 조작을 설계하는 근거로 사용한다. 해당 지침은 그래프 조작만으로 학습효과가 입증된다는 뜻은 아니다.
- 텍스트 전용 출력에는 표 행·코드가 보존되지 않았으나, HTML 변환본에서 `[9수02-14]`~`[9수02-18]` 코드와 문구를 모두 복구했다. 5개 문구를 변환 원문과 공백 정규화 비교해 전부 일치시켰다. 코드 확인은 콘텐츠 승인과 별개이므로, 기존 판본 미지정 일차함수 시범에 정식 판본·코드를 부여하지 않는다.
- 공식 고시 페이지는 제목·고시 번호·등록일·첨부에 수학과 별책이 포함된 것을 브라우저 화면으로 확인했다. 첨부 페이지 자체와 실제 텍스트 추출을 함께 보존했으며, 시범은 교사 검수·사용성 시험·학생 파일럿 전까지 배포 승인 자료가 아니다.

### 중2 일차함수 시범의 성취기준 범위표 (코드·문구 원문 확인, 콘텐츠 연결은 부분)

교육부 고시 제2022-33호 별책 8 HWP를 HTML로 변환해 표 행을 복구한 뒤, 성취기준 코드와 문구를 직접 확인했다. HWP SHA-256은 위 감사 기록과 같다. 앞선 텍스트 전용 변환에서 표가 빠져 있던 한계를 HTML 변환으로 해소했다.

| 확인된 성취기준 | 공식 문구 | 현재 일차함수 시범의 상태 | 남은 제작·연결 |
|---|---|---|---|
| `[9수02-14]` | 함수의 개념을 이해하고, 함숫값을 구할 수 있다. | 현재 `y=ax+b` 시범에는 유한 입력-출력 대응 개념이 없음 | 기존 함수 대응 실험과 연결하고, 입력별 출력·함숫값을 먼저 확인하는 선수 블록 추가 |
| `[9수02-15]` | 일차함수의 개념을 이해하고, 그 그래프를 그릴 수 있다. | `y=ax+b` 식·표·그래프와 계수 조작은 부분 포함 | 일차함수/비일차함수 판별, 상황에서 식 만들기, 조작 전 좌표 예측 후 손으로 그래프 구성 추가 |
| `[9수02-16]` | 일차함수의 그래프의 성질을 이해하고, 이를 활용하여 문제를 해결할 수 있다. | 기울기·절편 변화와 변화량 퀴즈는 부분 포함 | 그래프에서 성질을 설명하고, 맥락의 조건으로 식·값을 구하는 독립 전이 문항 추가 |
| `[9수02-17]` | 일차함수와 미지수가 2개인 일차방정식의 관계를 설명할 수 있다. | 현재 일차함수 시범에는 포함하지 않음 | `ax+by=c`의 해를 좌표로 찍고 직선 위의 점과 연결하는 활동을 좌표·방정식 흐름과 편성 |
| `[9수02-18]` | 두 일차함수의 그래프와 연립일차방정식의 관계를 설명할 수 있다. | 현재 일차함수 시범에는 포함하지 않음 | 기존 연립일차방정식 시범과 두 직선의 교점·해의 개수 활동을 연결하고 중복 집필 방지 |

**제작 판정:** 2022 개정 기준 코드·문구는 공식 별책 8에서 확인됐다. 다만 현재 판본 미지정 HTML/BookData는 `[9수02-15]`~`[9수02-16]` 요구를 일부만 다루며, 정식 기준 매핑·교사 승인·배포 승인은 완료되지 않았다. 2015 개정 `[9수03-04]` 함수 개념 시범과는 별도 콘텐츠다. 아래 공식 지침에 따라 대응 관계 활동을 선행 흐름에 배치하되, 개별 교재 버전 연결은 교사 검수 전까지 `partial/draft`로 유지한다.

### 근거에서 뽑은 공통 학습 장면

`짧은 설명·핵심 조건 → 학생의 예측 → 조작/시각화 → 관찰을 수식·말로 설명 → worked example → 풀이 일부를 가린 문제 → 독립 연습 → 며칠 뒤 누적 회상`

Socratic 퀴즈는 한 번에 한 질문만 보여주고, 오답이면 답을 공개하는 대신 개념을 분해한 힌트 질문을 제공한다. 학생 입력과 분기 저장이 아직 지원되지 않는 화면에서는 선택지형 또는 “힌트를 열어 확인”하는 고정 콘텐츠로 제공하며 대화형이라고 부르지 않는다.

### 모듈 선택 및 효과 확인 게이트

- **애니메이션 선택 질문:** 학습목표가 변화의 순서·방향·누적을 이해하는 것인가? 그렇지 않다면 정적 그림·표로 설명 가능한지 먼저 확인한다. 동적 표현을 택하면 학생이 의미 단위별로 멈추고 다시 볼 수 있어야 한다.
- **조작 도구 선택 질문:** 조작 변수가 목표 개념과 직접 연결되는가? 매개변수 변경 후 관찰 결과를 표·식·문장으로 설명할 수 있는가? 단순 클릭이나 그래프 구경만으로 끝나면 도구 퀴즈로 승인하지 않는다.
- **Socratic 질문 선택 질문:** 다음 질문이 학생의 실제 오개념이나 풀이 단계에 맞는가? 문제 난도·선수 지식과 어긋나면 하위 질문을 강제하지 않고 힌트 또는 완성 예제로 전환한다. 질문은 교사 검수된 분기로 먼저 운영하고, 생성형 모델의 자유 응답을 정답 판정기로 쓰지 않는다.
- **시범 효과 확인:** 콘텐츠 계약 테스트는 구조·수학식·작동 규칙 검증으로만 기록한다. 학습 효과를 주장하려면 기존 학습 방식과 비교 가능한 사전·사후 개념 문항, 새 조건 전이 문항, 지연 회상, 과제 완료·도움 요청·접근성 이슈를 별도 파일럿에서 측정한다. 작은 파일럿은 사용성·오류 발견 자료이지 인과적 학습 효과의 증명으로 간주하지 않는다.

## 체험 개념서의 모듈 라이브러리

모든 모듈을 매 차시에 다 넣지 않는다. 목표 개념에 가장 알맞은 1~3개를 골라 조작 시간과 생각 시간을 확보하고, 선택·응답·해설은 학생이 제어할 수 있게 한다. 모듈 효과는 원고의 설계 가설이며 실제 학생 파일럿 전까지 검증된 상품 효과라고 부르지 않는다.

| 모듈 | 학생 행동과 설계 | 다음 단계/검수 |
|---|---|---|
| 조작 가능한 수학 대상 | 수직선 점, 그래프 계수, 도형 점, 표본 수처럼 개념 변수를 직접 바꾼다. 축·단위·값 범위·초기화·키보드 조작을 함께 제공한다. | 조작 전 예측과 조작 후 이유 설명을 모두 답해야 한다. 특정 값만 우연히 맞히면 새 값으로 다시 확인한다. |
| 예측→관찰→설명 | 결과를 먼저 고른 다음 한 변수만 바꾸어 관찰하고, 바뀐 것/유지된 것을 수식이나 말로 표현한다. | 슬라이더 조작만으로 통과시키지 않고 도구를 닫은 전이 문항을 둔다. |
| 단계 애니메이션·수식 변환 | 풀이 또는 그래프에서 시간에 따른 변화가 학습목표일 때 3–5개 의미 단계로 쪼개고 각 단계에 짧은 문장·기호를 붙인다. 학생이 이전·다음·다시·정지를 조작한다. | 자동 재생을 기본으로 하지 않는다. 정지 화면, 대체 텍스트, 동작 줄이기 설정을 검수한다. 변화가 목표가 아니면 정적 표현을 우선한다. |
| 완성 풀이→가린 풀이→독립 풀이 | 정확하고 읽기 쉬운 완성 예제를 먼저 보여주고, 선택한 핵심 전환 1~2곳에서만 이유 묻기/힌트 열기를 둔다. 이후 도움을 줄인 새 문제로 간다. | 자기설명 질문을 모든 단계에 강제하지 않는다. 초보 학습자에게 완성 예시를 먼저 제공하고, 질문 프롬프트 유무에 따른 혼란·완료율을 파일럿에서 점검한다. 예제를 평가 문항으로 재사용하지 않는다. |
| 오류 탐정 | 잘못된 전개·그래프·조건 해석을 보여주고, 처음 틀어진 지점과 오류 이유를 찾는다. | 정오답만 피드백하지 않고 오류 유형에 맞춘 개념 복습 및 새 문항으로 연결한다. |
| 먼저 풀어보기→정리 | 배운 절차를 설명하기 전에 짧은 낯선 문제를 풀어 여러 접근을 만들고, 이어지는 설명에서 핵심 구조·조건을 비교한다. | 막막한 무힌트 문제를 길게 방치하지 않는다. 사전 지식이 필요한지 확인하고, 비교·정리 단계와 완성 예제를 반드시 뒤따르게 한다. |
| 대비 사례 비교 | 정답 풀이와 흔한 오답, 또는 조건 하나만 다른 두 문제를 나란히 놓고 결정적 차이를 찾는다. | 차이점을 학생이 말·식으로 설명하게 하고, 숫자만 바꾼 동일 문항이 아니라 새 조건의 적용 문제로 확인한다. |
| 단계형 회상 퀴즈 | 설명을 덮고 핵심 정의·조건·풀이 선택을 짧게 떠올린 뒤 즉시 정답 근거를 확인한다. | 퀴즈 결과는 학습 진단 근거이지 학생의 능력 고정 판정이 아니다. 단원 맥락과 문항 난이도를 기록한다. |
| Socratic 하위 질문 | `구할 것 → 주어진 조건 → 연결 관계 → 다음 풀이 선택` 중 현재 막힌 지점에 맞춰 질문을 하나씩 제시한다. 오답은 답 대신 작은 힌트로 이어지며, 복잡도·선수 지식과 맞지 않으면 완성 예제로 전환한다. | 분기는 교사 검수하고, 완전한 대화형은 실제 입력·상태 저장 구현이 확인된 경우에만 표시한다. 독립 HTML의 고정 선택형 퀴즈와 앱 기능을 구분한다. |
| 회상·간격 복습 | 이전 단원 핵심을 며칠/몇 회 뒤 짧게 다시 떠올리고 다른 표현과 섞어 본다. | 복습 간격은 고정된 학습법으로 과장하지 말고, 실제 수업 계획에 맞춰 교사가 조정한다. |
| 확률·통계 반복 실험 | 난수 시행을 학생이 늘리거나 다시 시작하고 상대도수와 이론값을 비교한다. | 한 번의 무작위 결과를 법칙으로 오인하지 않도록 여러 실행 결과와 유한 시행의 변동성을 설명한다. |

위 라이브러리는 IES의 학습 간격·worked example·표상 연결·회상/설명 퀴즈 권고, 디지털 수학 도구 메타분석 및 현재 과목별 단원 아이디어를 설계 요구로 번역한 것이다. 특히 활동량이 늘어도 학습이 보장되는 것은 아니므로, 매 모듈에는 목표 개념·학생의 관찰 행동·독립 확인 문제를 함께 기록한다.

### 추가 검토한 교육법과 적용 한계 (2026-10-11)

- **시각 표상과 풀이 과정 성찰:** What Works Clearinghouse의 4–8학년 수학 문제해결 가이드는 시각 표상 지도와 풀이 모니터링·성찰을 강한 근거 권고로 분류한다. 따라서 그래프 활동에는 그림만 제공하지 않고 “무엇이 변했고 무엇이 유지됐는가”를 말·식으로 설명하는 칸을 둔다. 이 권고를 고등 전 과정의 효과 보장으로 확대하지 않는다.
- **Productive Failure(생산적 실패):** Kapur의 연구는 개념 설명 전 문제 해결 시도를 배치한 뒤 정리·교수하는 설계를 다룬다. 선행 지식이 있는 학습자의 아이디어를 드러내는 데 유용한 설계 후보지만, 무힌트 난문항을 던져 두는 방식으로 오해하지 않는다. 문제 시도 뒤 비교 사례와 정확한 개념 정리를 반드시 제공한다.
- **오류 비교·설명 프롬프트:** 분수 비교를 다룬 연구에서는 학생 시도 이후 오답과 정답 예시를 비교하도록 한 질문이 학습에 도움이 됐다. 따라서 오답을 보여줄 때는 “틀림” 판정만 띄우지 않고 처음 잘못된 판단과 그 이유를 찾게 한다. 이 단일 주제 결과를 모든 수학 단원의 효과로 일반화하지 않는다.
- **동적 기하·디지털 도구:** 동적 기하 소프트웨어 메타분석은 포함된 준실험 9편, 참가자 587명의 성취도 결과를 종합했다. 표본·연구 수가 제한되므로 ‘조작형이면 항상 더 잘 배운다’고 쓰지 않는다. 도구는 목표 개념, 조작 전 예측, 조작 후 설명, 도구 없는 전이 문제와 함께 둔다.
- **회상·간격 연습:** 수학 문제풀이에서 회상 연습 효과가 맥락에 따라 달라질 수 있고, 2025년 초등 곱셈 연구는 간격·풀이 예시의 주효과를 확인하지 못했다. 따라서 고정된 간격이나 보편 효과를 주장하지 않고, 짧은 누적 퀴즈를 설계 후보로 쓰며 실제 파일럿에서 확인한다.
- **과목·단원 편성 교차 확인:** 지학사 공개 자료는 2022 개정 공통수학2 목차에 `함수와 그래프`와 하위 `함수의 뜻과 그래프`를 싣고 있다. 공통수학2에 함수 대응 관계 원고를 배치할 근거로만 썼다. 국가 성취기준 코드·문구와 선수 순서를 대조한 것은 아니며 출판물 문제·풀이·그림은 재사용하지 않았다.

참고: [IES WWC 4–8학년 수학 문제해결 가이드](https://ies.ed.gov/ncee/WWC/PracticeGuide/16), [Kapur, Productive Failure in Learning Math (2014)](https://doi.org/10.1111/cogs.12107), [오답 비교 프롬프트 연구 (2019)](https://doi.org/10.1016/j.learninstruc.2019.03.002), [동적 기하 소프트웨어 메타분석 (2014)](https://doi.org/10.2190/EC.51.3.c), [회상 연습과 수학 문장제 연구 (2023)](https://pmc.ncbi.nlm.nih.gov/articles/PMC9987560/), [간격 연습·풀이 예시 수학 연구 (2025)](https://doi.org/10.1016/j.learninstruc.2025.102103), [지학사 2022 개정 공통수학2 자습서 공개 자료](https://www.jihak.co.kr/upload/public/reference-book/pFEPU8dA63Uq7CVq/LRhRBmDvbsMhI8mU.pdf). 연구는 설계 근거이지 우리 교재 효과의 검증은 아니다.

## 한 개념의 원고 계약

1. `개념`: 2~5문장. 정의, 적용 조건, 왜 성립하는지 최소 한 가지 설명.
2. `먼저 예측`: 조작 전 답을 고르게 하거나 기록하게 한다.
3. `체험 도구`: 학생이 움직일 수 있는 변수 1~3개, 라벨·단위·범위·초기화·키보드 대안 포함.
4. `단계 애니메이션`: 보통 3~5개 장면. 각 장면에는 정지 상태의 설명을 함께 둔다.
5. `Socratic 확인`: 2~4개의 짧은 질문과 단계 힌트. 답을 바로 노출하지 않는다.
6. `worked example`: 풀이 이유를 적고, 다음 문항에서는 일부 단계를 비운 뒤 독립 문제로 전환한다.
7. `연습`: 개념 확인·표현 전환·새 조건 적용을 구분하고 해설/오개념 원인을 기록한다.
8. `회상`: 이전 개념을 간격을 두고 섞어 짧게 다시 묻는다.

## 디자이너 검토 및 재사용 디자인 기준

- 디자이너 회신(2026-10-12): 한 화면에 학습 질문 하나를 두고 `조작 → 관찰 → Socratic 질문 → 짧은 정식화 → 전이 퀴즈` 순서를 쓴다. 데스크톱은 시각 자료와 식·설명을 나란히, 모바일은 그림→조작→질문 순으로 쌓는다.
- 조작부는 터치 타깃 최소 44px, 현재값·단위·범위를 항상 보이고 키보드 조작·스크린리더 이름·색상 이외의 구분을 제공한다. 대비와 글자 확대를 고려하고, 애니메이션은 짧은 SVG/CSS 단계형으로 구성해 재생·정지·한 단계 보기 및 reduced-motion 정적 대안을 둔다. 자동재생에 의존하지 않는다.
- 모바일에서는 핵심 조작과 다음 동작이 손가락으로 닿는 위치에 오도록 설계하되, sticky/fixed 조작바는 실제 콘텐츠 가림·화면낭독 순서를 검증한 뒤 채택한다.
- 사인·코사인법칙 활동은 A/B/C와 맞은편 a/b/c를 색·라벨·식·수치에서 일관되게 쓴다. 주어진 값과 구할 값을 분명히 표시하고, 값 변경 시 도형·대입식·계산값을 함께 갱신한다. 불가능한 입력은 범위로 방지하거나 이유를 즉시 알린다. 취소·초기화, 단계형 힌트, 사용자가 요청한 풀이 공개, 반올림 안내를 둔다.
- 현재 시범에서 적용한 것: 한 화면 한 질문, 삼각형 라벨 대응, 입력값 및 범위 노출, 각도 변경 연동, 실행 취소·초기화, 오답 2단계 힌트 뒤 풀이 공개. 남은 것: 모바일 조작바, 텍스트 2배, 화면낭독기·색 대비 실기기 점검.
- 콘텐츠 파일에는 작은 수식·파라미터·페이지 단계만 보관하고 그래프 엔진이나 반복 영상 파일은 중복 탑재하지 않는다. 기존 `AiFlowGraphDocument` 그래프 블록은 BookData·모델·HTML 생성·교재 지면 렌더 테스트까지 확인했다. 사인/코사인법칙 식은 a,c 각 3개 값과 x축 각 4개 값의 36개 조합에서 수치 검산했다. 앱 WebView의 실제 브라우저 표시·조작과 화면낭독기/기기 조작은 여전히 미검증이다.
- 승인 전 체크: JSON 계약 파싱, 기존 지면 렌더, 그래프 식·파라미터·단위 검증, 실제 조작 반응, 키보드·모바일·화면낭독기·reduced-motion, 정답 노출 순서, 교사 검수. 시안 자문은 디자인 승인이나 사용성·학습효과 검증과 구분한다.

## 2026-10-12 추가 근거 점검

- 2000–2020년 동적 수학 소프트웨어 실험 107편, 참가자 10,507명을 종합한 2024년 3수준 메타분석은 수학 수행에 중간 정도의 평균 효과(d=.632)를 보고한다. 이는 도구 활용을 설계 후보로 지지하지만, 효과가 모든 단원·학생·도구에 동일하다는 뜻은 아니다. 따라서 단원별로 목표 개념, 조작 전 예측, 조작 후 설명, 도구 없는 전이 문제를 함께 두고 실제 파일럿에서 확인한다. [Ji et al. (2024)](https://doi.org/10.1177/07356331241226594)
- 애니메이션형 풀이가 정적 풀이보다 항상 낫다고 전제하지 않는다. WWC가 검토한 9학년 대수 애니메이션 연구는 32명 무작위 실험으로, 특정 학습 결과에 유망한 증거가 있다고 분류됐으나 표본이 작고 특정 단원·수업에 한정된다. 그래서 애니메이션은 자동재생 영상 대신 학생이 멈춤·단계 이동·다시 보기를 제어하는 짧은 장면으로 제공하고, 정지형 설명도 동등하게 둔다. [WWC study review](https://ies.ed.gov/ncee/wwc/Study/79865)
- 재사용 가능한 인터랙티브 교재 구현 참고로 Mathigon 공개 저장소를 확인했다. 이는 코드·콘텐츠 구조의 참고 사례일 뿐 한국 교육과정 정합성, 상업적 재사용 권한, 학습 효과의 근거로 간주하지 않는다. [Mathigon textbooks](https://github.com/mathigon/textbooks)
