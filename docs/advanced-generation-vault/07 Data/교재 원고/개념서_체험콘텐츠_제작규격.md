# 중·고등 수학 「개념서」 제작 규격

교육 근거와 과목별 체험 모듈 초안은 [체험수학_개념서_교육근거와_과목별모듈안.md](체험수학_개념서_교육근거와_과목별모듈안.md)에 정리했다. 해당 문서는 제작 제안이며, 판본별 성취기준 대조·교사 검수·앱 런타임 구현을 대체하지 않는다.

## 목표

- 책 이름은 과목별로 `중1 수학 개념서`, `고1 공통수학 1 개념서`처럼 모두 **개념서**로 통일한다.
- 긴 설명을 줄이되 개념의 정의·조건·이유를 생략하지 않는다. 학생이 먼저 예측하고, 조작하고, 설명하고, 확인하도록 설계한다.
- 영상 파일을 기본 산출물로 만들지 않는다. 애니메이션은 HTML/SVG/CSS/수식·그래프 데이터로 표현해 작은 용량으로 유지한다.
- 이 문서는 콘텐츠 설계다. 앱 수정, 교재 DB 등록, 수강 가능/판매 승인을 뜻하지 않는다.

## 기존 앱 디자인·상호작용 기반 검토

디자이너 작업 채팅에서 `Upstudy-hotfix` 저장소의 교재·그래프 화면을 검토했다(2026-10-11). 이는 코드 수정이나 사용자 화면 실측이 아닌 저장소 구조 기반 디자인 검토다.

- 교재 지면은 모바일 페이지 넘김, 목차·진행률, 필기 오버레이와 수식·표·풀이 단계·그래프 블록을 이미 지원한다. 교재 원고는 새 UI를 가정하지 말고 해당 블록으로 표현 가능한 짧은 설명과 콘텐츠 데이터를 우선한다.
- 그래프 기능은 기존 `AiFlowGraphDocument` 및 파라미터 슬라이더와 연결하는 방향으로 설계한다. 책마다 그래프 엔진을 포함하지 않고 작은 데이터만 저장한다.
- 그래프 편집기에는 수식 편집·계수 조절·확대/이동 UI가 있으나, 교재의 전체 코스 학습 흐름과 진도 저장까지 구현됐다는 뜻은 아니다. 코스 런타임은 별도 검증 전까지 미완성으로 취급한다.
- 권장 학습 장면: `짧은 설명 → 단계 애니메이션 → 직접 조작 → 조작 퀴즈 → Socratic 질문 → 풀이 예시 → 독립 연습 → 한 줄 정리`.
- 애니메이션은 자동 재생하지 않고 학생이 단계 이동·재생·정지한다. 동작 줄이기 설정에서는 즉시 전환한다. Socratic 퀴즈는 입력에 맞는 다음 질문을 제시하고 정답을 먼저 노출하지 않는다.
- 그래프가 불러와지지 않거나 오프라인이면 정적 SVG와 설명을 제공한다. 키보드 조작, 텍스트 대안, 색상 외 구별, 읽을 수 있는 슬라이더 값, 터치 영역, 확대 시 잘림을 검수한다.
- 권장 모바일 구성(390×844): 상단에 과목·개념·진행률, 본문에 짧은 설명, 기존 그래프 카드와 단계 조작, 그 아래 조작 퀴즈, 하단에 이전/다음 이동. 장식용 카드 수를 늘리지 않는다.

검토 위치: `Upstudy-hotfix/lib/sessions/textbook/ui/pages/book_page.dart`, `lib/sessions/graph_tools/API.md`, `lib/sessions/graph_tools/session/jsx_graph_page.dart`, `lib/features/course_runtime/README.md`. 이 경로는 별도 저장소의 구조 확인 기록이며, 현재 문서 저장소에 포함된 파일은 아니다.

## 한 개념 단원의 학습 리듬

1. **한 줄 목표와 선수 확인** — 이번에 할 수 있게 될 행동 하나, 필요한 선수개념 1~3개.
2. **먼저 예측/낮은 부담의 도전** — 그래프·도형·수식이 어떻게 변할지 짧게 예측한다. 새 개념의 일부 활동은 먼저 시도하고 이후 해설·정리로 통합하되, 막힌 채 방치하지 않도록 힌트와 완성 설명으로 연결한다.
3. **짧은 개념 설명** — 한 화면에 핵심 문장 1~3개, 기호의 뜻, 성립 조건. 용어만 암기시키지 않는다.
4. **차근차근 애니메이션** — 한 번에 한 변화만 보여주고 `이전/다음/정지/다시`를 제공한다. 움직임을 못 보아도 정지 화면과 문장으로 이해 가능해야 한다.
5. **직접 조작 실험** — 학생이 식·그래프·도형의 매개변수를 바꾼다. 원래 상태 복원과 키보드 조작을 지원한다.
6. **Socratic 질문** — 한 번에 한 질문, 답변에 맞춰 다음 힌트만 공개. 막히면 선택형 힌트, 그래도 막히면 worked example을 보여준다.
7. **풀이 예시 → 선택형 자기 설명 → 빈칸 풀이** — 정확한 완성 예시와 한 단계씩 가려진 풀이를 제공한다. 자기 설명 질문은 핵심 전환 일부에만 짧게 배치하고, 매 단계 강제하지 않는다. 초보 학습자에게 예시를 먼저 이해할 여지를 준다.
8. **도구 퀴즈와 독립 연습** — 도구에서 발견한 규칙을 말/식으로 표현한 뒤, 도구 없이 새 문항에 적용한다.
9. **회상·혼합 복습** — 단원 끝과 이후 학습에 이전 개념을 섞어 짧게 재확인한다. 문항을 반복 노출하지 않는다.
10. **오답 피드백** — 정답만 제시하지 않고 `어느 단계에서 갈렸는지 → 확인할 개념 → 새 문항`을 연결한다.

## 과목별 활동 유형

| 분야 | 우선 체험 활동 |
|---|---|
| 수·대수 | 식 타일/계수 조작, 식과 표·그래프 변환, 등식 양변 변화 추적 |
| 함수·미적분 | 매개변수 슬라이더, 확대/축소, 접선·변화율·누적량의 단계 재생 |
| 기하 | 점을 끌어도 유지되는 성질 찾기, 보조선 전후 비교, 좌표·벡터 성분 조작 |
| 확률·통계 | 표본 추출을 반복해 이론값과 비교, 자료 분포·대표값 변화 관찰 |
| 문장제·모델링 | 현실 상황의 변수 선택, 그래프/식 구성, 가정 변경과 결과 비교 |

AI 대화는 수학적 근거를 확정하는 채점기로 사용하지 않는다. 준비된 분기형 Socratic 문답을 기본으로 하고, 생성형 피드백은 별도 안전성·정확성 검증을 거친 뒤 선택 기능으로 검토한다.

## 저용량·접근성 규칙

- 기본 그래픽은 SVG/CSS와 기존 그래프 런타임을 사용하고, 반복되는 장면은 파라미터만 바꾼다. MP4/GIF 연속 강의는 기본 경로에서 제외한다.
- 애니메이션은 3~6개의 의미 단위로 끊고, 사용자가 다음 단계로 진행한다. 자동재생은 기본 끔, `prefers-reduced-motion`에서는 정지 화면으로 대체한다.
- 각 애니메이션에 정지 이미지에 해당하는 대체 설명을 제공한다. 색만으로 정답/오답 또는 그래프 의미를 구별하지 않는다.
- 인터랙션에는 초기화, 레이블, 단위, 허용 범위, 키보드 조작을 제공한다. 모바일은 슬라이더와 확대가 겹치지 않도록 세로 배치한다.
- 저장/추적 데이터는 정답 여부와 개념 ID 등 최소 항목만 설계한다. 학생이 입력한 자유서술은 별도 동의·보존 정책 없이 수집하지 않는다.

## 기존 저장 계약과 구현 경계

- 앱에 이미 `AiFlowGraphDocument`(function/line/scatter, expression, parameter, viewport) 및 `buildJsxGraphEmbed`(웹 iframe/native WebView) 경로가 있다. 개념서 그래프는 동일 계약을 참조하고 그래프 구현을 복제하지 않는다.
- 저장 계약은 하나가 아니다. 서버의 `TextbookChapter` 요청은 `title`, `intro`, `sections`와 섹션의 `title`, `paragraphs`, `images` 중심이지만, Flutter `BookChapter`는 `pages`, `visuals`, `graph`를 직렬화한다. `BookPage`와 `BookContentBlock`은 그래프·수식·문항·힌트·정답 등의 제한된 타입을 지원한다.
- `BookData`의 graph 블록은 기존 `BookWidget`에서 `_TextbookGraphCard`와 `buildJsxGraphEmbed`로 렌더링되고, 그래프 문서의 파라미터 조작부를 유지한다. 반면 question/answer/hint/thinking 블록은 편집용 정보 카드다. Socratic 분기·학생 답 입력·정답 분기·진도 저장은 이 콘텐츠 스키마에서 실행되지 않는다.
- 런타임 코드 대조 확인: 그래프 문서는 function/line/scatter 항목, 여러 parameter ID, 각 항목의 expression을 직렬화하고, 임베드 HTML이 파라미터 슬라이더 입력마다 그래프를 다시 렌더링한다. 수식 검증기도 parameter map을 받아 변수 이름을 바인딩한다. 따라서 `m1`, `b1`, `m2`, `b2`를 조절하는 두 직선 시범은 기존 계약에 맞는다.
- 독립 HTML 브라우저 확인(2026-10-11): 로컬 브라우저에서 두 직선·교점 `(2,2)`와 네 슬라이더가 표시되고, ‘하나’를 선택해 제출하자 현재 그래프 상태에 맞는 정답 피드백이 나타났다. 화면 캡처는 해당 시범 HTML의 데스크톱 배치 증거다. 이는 Flutter 앱 임베드 내부의 터치·슬라이더 E2E 또는 모바일 실측을 대신하지 않으며, 별도 HTML의 응답 저장·진도 기록도 없다.
- 교재 그래프 카드는 현재 화면 폭에 따라 약 192/228px 높이로 고정된다. 복수 슬라이더를 넣는 활동은 작은 화면에서 그래프·조작부가 잘리지 않는지 실제 기기 검수가 필요하다. 런타임이 가진 슬라이더 지원만으로 퀴즈 응답 저장·분기·진도 저장까지 지원한다고 간주하지 않는다.
- HTML 단계 애니메이션은 앱 책 모델에서 직접 불러오는 기능이 확인되지 않아 독립형 보조 시범물로 둔다. 앱을 수정하지 않고 콘텐츠만 제작하며, 서비스 등록 때는 기존 `BookData` 필드로 표현 가능한 활동과 별도 런타임/API가 필요한 활동을 구분한다.
- 배포 가능 여부와 라이선스·교육과정 근거가 검증될 때까지 원본 상태는 `draft`다.

현재 상세 시범 단원의 구조 검증 기록:

- `공통수학1_꼭짓점형_BookData_시범.json`: `BookData.toCreateJson()`과 `BookChapter.pages` 구조를 따르는 3개 페이지·9개 콘텐츠 블록. 그래프 2개와 변수 슬라이더 3개를 포함한다. `m>0`으로 제한해 이차항 계수가 0이 되는 경우를 피했다.
- JSON 파싱, 페이지 템플릿·블록 enum 이름, 그래프 매개변수 범위 검증 통과. 앱 저장 API 왕복은 검증하지 않았다.
- `공통수학1_꼭짓점형_단계애니메이션.html`: 인라인 SVG/CSS/JS, 단계 수동 이동, 동작 줄이기 설정, 두 개 답 선택 퀴즈 및 즉시 피드백. 인라인 JavaScript 문법 검증 통과. 이 구형 공통수학1 HTML 자체의 실제 브라우저 상호작용은 여전히 미완료다. (일차함수·통계적확률 시범은 별도 브라우저 검증함.)
- 앱 `BookContentBlock`의 question/answer는 렌더링 데이터이며 입력 채점·분기 기능이 확인되지 않았다. HTML 퀴즈는 독립 시범물이고 학생 응답을 저장하지 않는다.

### 디자이너 검토: 기존 구성 재사용과 미지원 경계

2026-10-11 디자인 협업 채팅의 저장소 조사 결과를 반영했다.

- 교재 화면의 모바일 페이지 넘김·목차·진행률·필기 레이어와 그래프 도구의 수식 편집·계수 조절·확대/이동은 기존 화면/도구를 재사용한다. 근거 파일: `lib/sessions/textbook/ui/pages/book_page.dart`, `lib/sessions/graph_tools/session/jsx_graph_page.dart`, `lib/sessions/graph_tools/API.md`.
- 그래프 문항은 `AiFlowGraphDocument`와 파라미터만 교재에 넣고 그래프 엔진을 복제하지 않는다. 기존 그래프 런타임은 JSXGraph CDN에 의존하므로 오프라인 정적 대체 화면은 별도 검증이 필요하다. 근거 파일: `lib/sessions/graph_tools/README.md`.
- 권장 장면 흐름은 `짧은 설명 → 단계 애니메이션 → 직접 조작 → 조작 퀴즈 → Socratic 질문 → worked example → 독립 연습 → 한 줄 정리`다. 설명·활동은 한 화면에 과밀하게 쌓지 않고 순차 제시한다.
- 코스 런타임은 조사 시 `Phase 0 scaffolding`으로 판정되어 교재 학습의 순서·분기·진도 기록까지 제품 기능으로 간주하지 않는다. 실제 연결은 별도 검증 대상이다. 근거 파일: `lib/features/course_runtime/README.md`.
- 모바일은 그래프와 편집 패널을 접고 펼치며, 단계 이동 키보드 조작·텍스트 대안·색 외 구별·터치 영역·reduced-motion·오프라인 정적 대체를 검수한다.

## 추가 시범: 확률과 통계의 통계적 확률

2022 개정 수학과 교육과정 별책 8의 `[12확통02-01]`(확률 개념·기본 성질)과 확률 영역의 적용 유의사항을 원문에서 대조했다. 통계적 확률은 충분한 시행을 위해 공학 도구를 사용할 수 있다고 안내되어 있어, 두 번째 상호작용 유형으로 난수 주사위 반복 실험을 설계했다.

- 학생이 시행 수를 선택하고 실험을 다시 시작하거나 누적해서 추가한다.
- 누적 상대도수와 수학적 확률 `1/6`을 비교하고, 유한 시행에서 일치가 보장되는 것처럼 설명하지 않는다.
- 실제 저장/평가 기능은 없는 독립 HTML이다. 고정형 교재 원고와 별도로 학생 반응을 기록하는 앱 런타임이 필요하다.
- 파일: `고등수학_확률과통계_개념서_통계적확률_시범원고.md`, `고등수학_확률과통계_통계적확률_체험형_시범.html`.

추가 연구 근거 및 설계 반영(2026-10-12):

- [Ji, Guo & Song, Effects of Dynamic Mathematical Software on Students’ Performance (2024)](https://doi.org/10.1177/07356331241226594): 107개 연구·10,507명·138개 효과크기의 3수준 메타분석에서 전체 효과는 중간 수준(d=0.632, 95% CI [0.550, 0.713])이었다. 조절 분석에서는 가까운 전이 평가가 먼 전이보다 높았고, 학생이 도구를 독립적으로 사용한 연구에서 효과가 더 컸으며, 개입 기간과 문화적 배경도 조절 요인이었다. 따라서 그래프 조작을 성취 향상 자체로 홍보하지 않고, 조작 후 새 문제 전이와 독립 풀이를 별도 확인한다.
- [Berthold et al., Computer game-based mathematics education: Embedded faded worked examples facilitate knowledge acquisition](https://www.sciencedirect.com/science/article/pii/S0959475216302316): 네덜란드 직업교육 과정의 12.3~15.3세 학생 103명 중 분석 대상 93명을 대상으로 비례 추론 게임을 비교했고, 풀이 예시를 점차 줄이는 집단이 비교 집단보다 향상(d=0.62)했다. 특정 국가·학년 트랙·주제의 결과이므로 중고등 전 과목 효과로 일반화하지 않는다. 적용은 `완성 예시 → 일부 단계 비우기 → 독립 문항`을 후보 리듬으로 두고 과목 파일럿에서 검증한다.
- [Razzaq, Ostrow & Heffernan, Effect of Immediate Feedback on Math Achievement at the High School Level (2020)](https://pmc.ncbi.nlm.nih.gov/articles/PMC7334720/): 10~11학년 243명 무작위 교차 연구에서 컴퓨터의 즉시 정오 피드백과 힌트를 받은 조건이 사후검사에서 피드백을 늦게 받은 연습 조건보다 유리했고, 사전 지식이 낮은 학생의 이득이 더 컸다고 보고했다. 따라서 피드백은 단순 정오 표시보다 오류 단계·힌트·풀이·새 문항을 연결하되, 개인별 효과와 학습효과는 우리 서비스 파일럿 전까지 주장하지 않는다.
- 위 근거를 제작 규칙으로 변환한다: (1) 도구 조작 전 학생 예측을 받고, 조작 후 관찰값을 말이나 선택으로 설명한다. (2) 예제 풀이를 한 단계씩 가린 뒤 독립 문항으로 넘긴다. (3) 오답에는 정답 노출 전 단계형 힌트를 주고 다른 조건의 재평가 문항을 연결한다. (4) 단순 조작 성공과 개념 이해를 구분하도록 근접 전이 문항과 새로운 표현·조건의 전이 문항을 각각 둔다. 이 규칙은 문헌을 반영한 제작 가설이지, 본 교재에서 효과가 입증됐다는 뜻은 아니다.

- 설명 순서의 순환 가능성을 발견해, `y≥0`을 미리 가정하지 않고 `√(x²+(y-p)²)=|y+p|`에서 시작하도록 수정했다. 제곱근과 절댓값이 모두 비음수라 제곱은 동치이고, 전개 후 `x²=4py`, `p>0`에서 `y≥0`을 얻은 다음 `|y+p|=y+p`를 결론으로 둔다.
- 학생 원고·BookData·HTML 단계와 선택형 확인 퀴즈를 같은 논리 순서로 맞췄다. 브라우저에서 세 번째 단계 문구와 정답 피드백을 확인했고, `flutter test --no-pub test/concept_textbook_prototype_json_test.dart` 19개 테스트가 통과했다.
- 이 검증은 해당 대수적 유도와 구조화 데이터의 기존 BookData 계약 적합성을 확인한다. 교육과정 기준 적합성, 교사 검수, 앱 내 HTML 연결이나 학생 학습효과를 입증하지 않는다.

## 확률과 통계 누적 시행 체험 보강 (2026-10-11)

- 기존 시뮬레이션은 주사위 시행을 한 번에 계산해 누적 그래프 변화가 보이지 않았다. 선택한 시행을 작은 묶음으로 순차 공개하고, 진행 중 정지해 현재 결과를 보존하며, 같은 실험에 추가 시행을 연결하도록 수정했다. 실행 중 중복 요청을 막기 위해 조작을 잠그고, 최대 누적 5,000회 제한은 유지했다.
- 그래프 세로축이 `0~0.5`였던 점도 보완했다. 상대도수의 가능한 전체 범위 `0~1`로 확장해 작은 시행에서 높은 관찰값이 나와도 잘리지 않게 하고, 이론 기준선 `1/6`은 고정했다. x축 정규화는 실행 중 목표 시행 수에 맞춰 진행 위치를 보여준다.
- 학생 원고에는 중간 정지 결과 보존, 추가 실행, 새로고침 시 실험 기록 미보존을 명시했다. 움직임 감소 설정이면 즉시 계산하고, 실행 중 설정이 바뀌면 현재까지의 표본을 남기고 정지하도록 했다.
- 브라우저 확인: 100회 선택 후 순차 실행(760ms 시점에 상태 48/100, 계수 스냅샷에서는 64회), 중지 시 70회 결과 보존, 같은 실험에 100회 추가 후 총 170회 완료를 관찰했다. 매 단계 수치는 무작위라 검증 기록에서 특정 6의 횟수를 정답으로 취급하지 않았다. `3/12=1/4` 퀴즈 피드백과 실행 중 버튼 잠금, 그래프·축·진행 화면 캡처도 확인했다.
- 한 브라우저에서의 독립 HTML 데스크톱 검증이며 reduced-motion 전환의 실제 UI 실측, 모바일 폭, 앱 내 연결·응답 저장, 학습 효과 및 교사 검수는 미완료다. 애니메이션은 설명용 시각화이지 이론 확률에 가까워지는 것을 매 표본 경로가 보장한다는 주장이 아니다.

## 중등 그래프 해석 과제 설계 근거 (2026-10-12)

- Johnson 외(2021)의 질적 연구는 15–17세 중등학생 13명이 디지털 그래프 과제를 수행할 때 그래프를 양 사이 관계로 읽거나 물체의 문자 그대로의 경로·모양으로 읽는 서로 다른 관점이 나타난다고 보고했다. 제한된 표본의 질적 연구이므로 효과 크기나 모든 학생에게 적용되는 교수법을 입증하지 않는다. [논문 원문](https://link.springer.com/article/10.1007/s40751-020-00061-9)
- 설계 반영: 축 이름·단위 먼저 확인 → 표를 좌표로 옮김 → 학생이 시점별 값을 조절 → 그래프 구간을 단계별로 공개 → 선택한 상황의 양 변화로 설명. 걷기 맥락에서는 그래프의 감소를 지도 위의 실제 경로와 동일시하는지 질문한다.
- 그래프 모양 맞히기보다 두 축의 양 사이 관계를 말하도록 한다. 동시에 3개 맥락(거리·물의 양·기온)을 제공해 축 해석을 반복하되, 숫자 조정에 따른 답은 현재 값에서 다시 산출한다.
- 이는 해당 연구의 reasoning/exploration·축 간 관계 설계 취지를 제품 수준에서 시험하는 시범이다. 대상 연구가 다룬 과제와 다른 단원·나이이며, 이 자료의 학습 성과를 보장하지 않는다. 교사 검수와 학생 파일럿에서 오개념 변화 및 전이 여부를 별도로 평가해야 한다.
