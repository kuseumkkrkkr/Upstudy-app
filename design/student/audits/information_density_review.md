# 학생용 시안 정보 밀도 순회 분석

분석일: 2026-07-14  
대상: 학생용 HTML 시안 25개 화면  
검토 조건: PC 1280×900, 모바일 500×1000 첫 화면 캡처 각 25장

> 이 문서는 변경 전 진단 기록이다. 진단에 따른 축소·통합 결과와 재검증은 `density_redesign_summary.md`를 참고한다.

## 결론

현재 시안은 모든 화면의 정보가 많은 것이 아니다. 실제 문제는 다음 네 가지가 겹치는 화면에 집중되어 있다.

1. 기능·메서드·엔드포인트 검증 원장이 일반 사용자 화면에 노출된다.
2. 큰 제목, 설명, 요약 지표가 같은 내용을 반복해 첫 행동을 아래로 민다.
3. PC의 카드 묶음을 모바일에서 우선순위 재편 없이 세로로 쌓는다.
4. 한 기능을 여러 컨테이너와 버튼으로 반복해 실제 정보량보다 복잡해 보인다.

따라서 기능을 삭제하는 방식으로 줄이면 안 된다. 검증 원장은 전용 패널로 숨기고, 반복 요약을 합치며, 모바일에서는 사용자의 다음 행동을 먼저 배치해야 한다. 시험지·문제풀이·교재 리더·그래프처럼 조작 자체에 필요한 정보 밀도는 보존한다.

## 판정 기준

- **매우 높음**: 첫 화면에서 주 행동이 보이지 않거나, 같은 정보가 여러 블록에 반복됨
- **높음**: 핵심 기능은 보이지만 부가 요약·버튼·컨테이너가 경쟁함
- **적정**: 한 화면의 주 행동과 보조 정보 관계가 명확함
- **낮음/과장**: 정보는 적지만 큰 히어로와 여백 때문에 행동 도달이 늦음
- **기능 밀도**: 작업 수행에 필요한 캔버스·도구·문항 정보이므로 단순 축소 대상이 아님

## 공통 문제

### 1. 사용자에게 노출된 검증 원장

`기능 태그`, `보존 계약`, `METHOD`, `ENDPOINT`는 기능 누락 검증에는 필요하지만 학생이 읽을 정보가 아니다. 특히 모바일에서는 정상 콘텐츠 뒤에 또 하나의 긴 섹션처럼 나타난다.

- 일반 화면에서는 숨긴다.
- 시안 검수용 `기능 매핑` 패널 또는 개발자 모드에서만 연다.
- 실제 기능·알고리즘·엔드포인트 보존 여부는 원장 데이터로 계속 검증한다.

### 2. 모바일의 단순 세로 적층

PC에서 2~4열로 보이는 통계·카드가 모바일에서 모두 한 열이 되며 첫 행동보다 앞선다. 숫자 요약은 2×2 또는 한 줄 요약으로 합치고, 상세 수치는 펼쳐보기로 이동해야 한다.

### 3. 큰 히어로의 과도한 사용

홈, 복습, 레벨 테스트, 아레나, 회원가입은 정보가 많아서가 아니라 큰 소개 영역이 첫 화면을 점유한다. 반복 방문 화면은 설명보다 `이어하기`, `복습 시작`, `대결 방식`, `입력 폼`을 우선해야 한다.

### 4. 카드 수보다 경계 수가 많음

리스트의 각 행, 요약 수치, 필터, 설명이 모두 별도 둥근 컨테이너를 사용한다. 관련 정보를 한 표면 안에서 구분선과 타이포그래피로 묶으면 기능을 삭제하지 않고도 가독성을 높일 수 있다.

## 우선순위

### P0 — 다음 수정에서 반드시 처리

1. 모든 일반 화면에서 기능 태그·메서드·엔드포인트 원장 숨김
2. 설정 화면 빈 렌더링 원인 확인
3. 학원 화면을 기능 목록에서 실제 학생 작업 화면으로 교체
4. 모바일 코스 상세의 지표 적층 제거
5. 모바일 코스 학습에서 현재 미션을 첫 화면으로 이동
6. 복습 히어로를 행동 중심 요약 바로 축소
7. 모바일 Flow 분석에서 원래 Flow 캔버스를 먼저 표시

### P1 — 구조를 정리하면 체감이 큰 화면

1. 홈 인사 히어로 축소와 시작 CTA 중복 제거
2. 코스 탐색 검색·필터·OVR 통합
3. 그룹 상세의 상단 액션과 설명 축약
4. 책가방의 통계·검색 통합
5. 친구/소셜 우선 알림 통합
6. 마켓플레이스 필터 중복 제거
7. 회원가입 첫 입력 도달 단축

### 유지해야 할 작업형 화면

- 문제 풀이
- 시험지 풀이
- 교재 리더
- 그래프 그리기
- 채팅

이 화면들은 정보가 많아 보이더라도 대부분 직접 조작에 필요한 기능 밀도다. 카드 수를 줄이겠다는 이유로 도구, 페이지 상태, 답안 상태, 캔버스 영역을 삭제하면 UX가 악화된다.
