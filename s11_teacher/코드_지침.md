# s11_teacher 코드 지침

## 0) 공통 원칙
- `flutter analyze`는 PR/반영 전 필수로 실행한다.
- 변경 범위를 최소화하고, 문자열 깨짐이 의심되는 라인은 즉시 인코딩 점검(UTF-8) 후 수정한다.
- `BuildContext`는 비동기 경계 뒤에서 직접 사용하지 않거나, 사용 전 `mounted` 체크를 먼저 수행한다.
- 신규 위젯은 기존 디자인 시스템(`design_tokens.dart`)을 우선 사용하고, 임시 매직 넘버를 줄인다.

## 1) 컴파일 안정성
- 문자열 리터럴이 끊기지 않도록 작은 따옴표/큰 따옴표를 항상 같은 라인에서 닫는다.
- `String` 보간은 `'$foo'` 스타일보다 `${}` 또는 `$foo`를 활용한다.
- `StatefulWidget`에서 생성자 파라미터를 `super.key`로 전달한다.
- `addToFavorites` 같은 비동기 액션의 `setState`, `Navigator` 호출은 `mounted`를 확인한다.

## 2) 비동기와 상태 관리
- `FutureBuilder`, `ValueListenableBuilder`를 쓸 때는 `snapshot.connectionState`와 null 상태를 명확히 처리한다.
- `Dialog`/`BottomSheet` 내부에서 `TextEditingController`, `ValueNotifier`를 생성하면 `dispose`에서 반드시 해제한다.
- API 호출 함수는 `try/catch` + `finally`로 UI busy 상태를 보장한다.

## 3) 파일별 규칙
- `teacher_dashboard_page.dart`
  - 카드/영역 단위의 UI 조합은 `_FeatureCard`, `_buildHero` 같은 컴포지션 함수로 유지한다.
  - Glassmorphism 적용 시 `BackdropFilter` + 흐린 배경색 + 얇은 테두리를 조합한다.
  - 텍스트는 고정 문자열(한글/영문) 직접 삽입보다 상수로 관리 가능한 경우 상수화한다.
- `student_view_preview.dart`
  - 책 목차/검색/본문 렌더링은 단일 책임 함수로 나누고, 각 함수는 120줄 내외로 유지한다.
  - 함수명/변수명은 의미를 유지하고 주석은 최소화한다.

## 4) UI 가이드(Glassmorphism)
- 기본색은 다크톤 배경 + 고정된 포인트 컬러를 사용한다.
- `BackdropFilter`로 흐림 효과를 적용하고, 카드 배경은 반투명 흰색(`alpha 0.1~0.25`)로 둔다.
- 컨테이너는 `Border.all`로 경계선을 주고 `BorderRadius`는 과하지 않게(18~28) 적용한다.
- 텍스트 가독성을 위해 텍스트 대비 대비비를 확보한다.

## 5) 회귀 방지 체크리스트
- 화면 진입/뒤로가기/토글 동작에서 `setState` 경로가 안전한지 확인
- 라우팅 후 상태 갱신 시 `mounted` 확인
- 리스트에서 인덱스 접근 전 길이 경계 체크
- 신규 파일은 분석 경고(`deprecated_member_use`, `prefer...`)가 과도하게 쌓이지 않도록 정리
